## Обходит ли текущий стек стол сам?
Проверена D1 v3: trinary occupancy image (319x426, resolution.05, origin[-13.3,-10.4]). Для предыдущих start(-6.54,4.42) и goal(-6.1607,2.5495) все300 sampled centers прямой линии попали в pixel gray254 (free); не было ни одной occupied/unknown точки на centerline. Это согласуется с командой Nav2 ехать почти прямо. Статический global costmap содержит только D1 static+inflation. Scan obstacle layer подключён в local_costmap; он видит препятствие и RPP collision checker может остановить прямую команду, но global planner не получает этот слой и не строит динамический обход вокруг незаписанного стола.
Следовательно автономный обход именно незанесённого в D1 стола текущим конфигом НЕ подтверждён и ожидать его нельзя: вероятнее прямой маршрут с остановкой, когда локальная collision проверка видит стол. Если стол присутствует в D1 либо обход моделируется оператором отдельной waypoint целью, planner может строить статический путь. Это другой опыт, не динамическое local replanning.
Coordinator stop и adapter stop вызваны после Goal02, робот MC STAND/FSM4, adapter unarmed, свежая цель закрыта. Recorder Goal3 без движения остановлен.

Предыдущий conclusion «ожидать нельзя, стол не занесён» был поспешным и отозван. Local obstacle scan additionally guards the robot. Требуется новая цель на другой стороне центрального quadrilateral, чтобы реальный planner path проверить. Если коридор вокруг стола уже/равен effective body envelope, planner должен отказать, не ехать по unknown. Проверять path/goal и фактический ход по отдельной новой цели; предыдущая цель cancelled.
