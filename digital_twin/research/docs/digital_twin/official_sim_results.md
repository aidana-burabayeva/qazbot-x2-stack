# Официальный MC + MuJoCo в twin — запуск и первые измерения (2026-10-23)

Все запуски — в контейнере `qazbot-twin-sim:humble` (база `osrf/ros:humble-desktop-full`, digest `sha256:1db1e4e9…8178c`, плюс Nav2 из apt), `--network none`, ROS_DOMAIN_ID=87, ROS_LOCALHOST_ONLY=1, пользователь uid 1000. Проверено: в контейнере только `lo`, TCP к `192.168.1.66:22` → «Network is unreachable». Причина строгой изоляции: в `simulator/default.yaml` sim включает `net_plugin` с HTTP на `0.0.0.0:51822`, а официальный `run_docker.sh` использует `--network host`.
Робот `.66`: в этом блоке только чтение (калибровка, версии). Движений реального робота не было.

## Как запустить (проверено)
1. `docker run -d --name qazbot-twin-sim --network none …` (команда в истории; монтируются `vendor/official/{mc,sim}`, `runtime_x86/run/aimdk`, `runtime_x86/run/agibot_data`→`/agibot/data`, X11-сокет). Вместо `sudo mkdir /agibot` — каталог пользователя.
2. Сборка AimDK в контейнере: `colcon build` (5 пакетов, 2 мин 21 с, предупреждения только в `examples`).
3. **Порядок важен.** Если MuJoCo запущен раньше MC, робот падает до того, как MC держит суставы (pelvis спаунится на 0,68 м, суставы без момента). Рабочий порядок: `tools/twin/docker/inside_mc.sh` (MC, SIM-конфиг: `AGIBOT_SOFTWARE_HOME` не задан) → `set_mc_action SD` → затем `tools/twin/docker/inside_sim.sh`. Результат: z = 0,653 м, вертикаль 1,00 (стоит).
   Уточнение (26.10, повтор + `sim_steps_20261023.md`): со свежим MC `set_mc_action SD` отвечает ошибкой (`code=0`), пока нет `/aima/hal/joint/leg/state` и `/aima/hal/imu/torso/state` (лог MC: «2个前置依赖未就绪»). Воспроизводимая последовательность: MC → sim (робот падает) → `SD` → **перезапуск sim** → робот стоит. `start_sim.sh` имеет гонку `check_running_instance` (`pgrep -f` находит родительский `bash -c`): запускать через обёртки `tools/twin/docker/inside_*.sh`. `pkill -f` внутри `docker exec bash -c` убивает саму обёртку — вызывать `docker exec C pkill -f …` напрямую; иначе остаются два MC. `tools/twin/docker/sim_restart.sh` содержит порядок MC→SD→sim и в таком виде не работает.
4. Робот выбирается интерактивно в обоих скриптах (индекс `0`, `lx2501_3_t2d5`) — в скриптах подаётся `echo 0 |`.
5. Локомоция: `set_mc_action LD`, затем официальный `mc_locomotion_velocity` (источник `node.locomotion_velocity`, приоритет 40, timeout 1000, ADD→ENABLE; публикует 50 Гц ~5 с).
Измерения: `tools/twin/mc_probe.py` (odometry из sim), `tools/twin/docker/vel_test.sh`, `tools/twin/docker/summarize_probe.py`.

## Что публикует sim (проверено)
`/aima/hal/odom/state` ~490 Гц (world-frame поза с z; на стоянии z=0,653 — похоже на истину, без ковариаций, не подтверждено); `/aima/mc/leg_odometry` **в sim отсутствует** (в реальных bag есть); IMU torso/chest, joint states. Нет LiDAR и камер.
Предупреждения MC: `leg_joint_command worker missed wakeup time, diff 252 us, period 2000 us, miss 12,6%` (948 строк за запуск) — контейнер без RT-приоритетов, CPU делится с другими процессами; на динамику это влияет в неизвестной мере.

## Что это значит (осторожно)
- Официальная документация: «The current MC gait does not guarantee starting an in-place turn using angular velocity alone» (`sim_contents`, раздел Verify Motion Control). Это то же поведение, что Блокер 1, и оно **документировано производителем**.
- Sim-MC качественно воспроизводит оба наблюдения с робота: (а) фактическая скорость вперёд заметно выше команды, (б) поворот на месте при 0,5 рад/с срабатывает плохо (по часовой хуже), при 0,6 рад/с идёт в обе стороны. Количественно не совпадает (скорость ≈2,2× против 1,9–2,8× на роботе) и n=1: утверждать «twin точно воспроизводит MC» нельзя. Нужны повторы (≥5 на условие) и валидация на отдельных реальных данных.
- Версия MC: в sim `mc-x86-v1.0.0-20260522`, на роботе (PC1) **mc v1.1.0-r9-rc9**, mc_param v1.1.0-r9-rc3 (`20261023-twin-handoff.md`, `vendor/pc1_mc/`). Параметры локомоции идентичны, код раннеров различается — влияние не проверено (`20261023-twin-mcparam-diff.md`, H3).
- Нерешённое решение оператора (0,5 → 0,6) этими данными не принимается: sim — только инструмент сравнения вариантов до пробы на роботе.
