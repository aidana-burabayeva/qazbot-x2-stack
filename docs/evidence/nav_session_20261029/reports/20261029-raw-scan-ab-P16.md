## Design
- Input: /aima/hal/sensor/lidar_chest_front/lidar_pointcloud, frame `lidar_chest_front`, ~10 Hz, ~25.3k pts, fields
  x,y,z,intensity (f32), ring (u16), timestamp (f64, ns AFTER header.stamp, 0..~95 ms) -> header.stamp = sweep START.
- Extrinsic lidar->LiDAR-IMU: x2.yaml extrinsic_R/extrinsic_T (= inverse of /tf_static lidar_chest_front->lidar_imu_chest_front,
  re-read live today: t=(-0.0112,0.0045,0.0157), q=(0.4966,-0.5029,-0.4990,0.5014)). base_footprint = level_bridge definition
  (LiDAR IMU projected on floor, yaw = LiDAR forward axis LIDAR_FWD_IN_IMU) -> drop-in frame-compatible with /qazbot_lio/scan.
- Attitude: /aima/mc/leg_odometry (MC, ~150 Hz, pose of lidar_imu_chest_front in gravity-levelled leg_odom). The LiDAR IMU
  publishes identity orientation (accel/gyro only); torso IMU is in base_link at 430 Hz. Leg-odom roll/pitch used for levelling,
  its relative pose over <=0.1 s for per-point deskew (10 time slices, interpolated). Absolute x/y/yaw NOT used.
  Startup cross-check: leg_odom "up" vs LiDAR-IMU mean accel = 2.36 deg (standing).
- Slice/binning: imports level_bridge (Z_MIN=-0.65, Z_MAX=0.80 rel. IMU, FLOOR_MARGIN 0.035/m, 1440 bins, RANGE_MIN 0.45,
  clearing_endpoints) ; range_max 8.0, scan_every 2 (= live level_bridge params). Stamp = cloud stamp.
- Outputs ONLY: /qazbot_raw/scan, /qazbot_raw/scan_obstacles, /qazbot_raw/scan_clearing (I1 semantics via level_bridge.clearing_endpoints),
  /qazbot_raw/scan_low (experimental low slice z -0.80..-0.50 rel. IMU, margin 0.015/m = 0.11+0.015r .. 0.41 m above floor).
  No TF, no odom, no cmd/goal/initialpose (graph-checked: pubs only /qazbot_raw/* + rosout/parameter_events).
- CPU tricks: raw (serialized) cloud subscription, deserialize only every 2nd cloud; leg_odometry on a second never-spun node
  (KEEP_LAST 400) drained in batch via take_message + hand CDR parse (verified equal to deserialize_message).

  setsid nohup python3 /home/agi/control_backend/ws/src/lio/raw_scan_bridge.py --ros-args -r __node:=qazbot_raw_scan_bridge_nodeskew \
     -p prefix:=/qazbot_raw/nodeskew -p deskew:=false -p publish_clearing:=false -p scan_every:=1 -p range_max:=8.0 >> raw_nodeskew.log 2>&1 &
  python3 -W ignore ab_eval_motion.py 900 ab_motion_N.json <fastlio_pid> <level_bridge_pid> <raw_pid> <nodeskew_pid>
ab_eval_motion.py splits scans into moving/standing: moving = native odom |v|>0.05 m/s or |wz|>0.1 rad/s, or the adapter's
counters.published went up in the last 1 s. It also does the following:
  - Map pose at scan stamp = AMCL pose composed with the native-odom delta.
  - Pairs lio↔raw by nearest stamp (≤50 ms) and raw↔nodeskew on the same cloud (direct deskew effect).
  - Memory is bounded and observer CPU is low (the cloud is subscribed raw; only the stamp is read).
Caveat: lio↔raw pairs only exist while both pick the same parity of every-2nd cloud. A dropped cloud flips the parity.
lio↔nodeskew (every cloud) always pairs.
