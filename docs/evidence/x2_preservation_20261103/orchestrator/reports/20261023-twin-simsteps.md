## Найденные проблемы процедуры (важно для следующей попытки)
1. `pkill -f PATTERN` внутри `docker exec bash -c "..."` убивает сам bash-обёртку и не трогает цель → старый MC остался жив, в первой
   попытке работали ДВА MC одновременно, робот упал (z=0.076). Решение: `docker exec C pkill -f PATTERN` без bash -c (так сделано в sim_restart.sh).
2. Порядок «MC → SD → sim» из official_sim_results.md с чистым MC не воспроизводится: MC отвечает на SetMcAction SD ошибкой (code=0,
   Mode name пустой), пока нет /aima/hal/joint/leg/state и /aima/hal/imu/torso/state (лог MC: «MC未能启动, 2个前置依赖未就绪»).
   Вероятно, в исходном запуске SD «прошёл» потому, что MC уже был в готовом состоянии. Нужна проверка: MC → sim → немедленный опрос SD.
3. Официальный `start_sim.sh` имеет гонку в `check_running_instance` (pgrep -f находит подоболочку самого скрипта) → «Another instance
   ... already running» и выход; в последней попытке 6 из 6 запусков отказали. Обход: запускать `aima-sim-app` напрямую с теми же env/cfg,
   либо копию start_sim.sh без этой проверки (как новый файл в twin/docker/).
4. Официальный пример mc_locomotion_velocity после 5 с продолжает публиковать нули (spin) — коаст с нулевыми командами есть; zombie-процессы
   от прошлых `timeout`-запусков.
