# T5 map→odom jump: геометрически корректная метрика (twin, 2026-10-28)

Область: только цифровой двойник. Код физического X2 (`control_backend`) не менялся; кандидат лежит в `candidates/t5_geometry/` (`t5_geometry.patch`, база = C3 как установлено на роботе из `C3_seed_review.tar.gz`).

## Подтверждённая проблема
T5 сравнивал translation и yaw трансформа `map→odom`. Это не смещение робота: translation зависит от того, где лежит начало odom. Запись S4 (`S4_takeover_b_1132`, 1793100629.517): translation 0.1019 м (порог 0.10) → сброс `initialized`; тот же шаг, применённый к текущей позе робота, сдвигает его на 0.0396 м. Воспроизведено из сохранённого bag (`scripts/t5/extract_tf.py`, `replay_steps.py`): единственный шаг bag, old=0.1019, robot=0.0396.

## Изменение (порог не менялся: 0.10 м / 0.10 рад)
`correction_at(prev, new, odom)`: смещение робота = |compose(new, odom) − compose(prev, odom)|, yaw как раньше. odom = odom→base на момент обновления (узел кладёт в очередь пару (map_odom, odom); evaluate() и разрыв TF используют `inp.odom_base`). Нет odom → старое правило по translation (не слабее). C3 (сброс истории при initialpose) сохранён.

## Решение по B2 (ужесточение)
Принято как намеренное: yaw 0.06 рад на плече 6 м сдвигает робота на 0.36 м, это реальный глобальный сдвиг, а прежнее «пропустить» было следствием выбора начала odom. На 16 записанных шагах B2-подобных случаев нет (ни один шаг с малым translation не даёт сдвиг >0.10 м), то есть на практике ужесточение ничего не добавило. Пороги не менялись. Откат: ветка кода с `odom=None` возвращает старое правило.
