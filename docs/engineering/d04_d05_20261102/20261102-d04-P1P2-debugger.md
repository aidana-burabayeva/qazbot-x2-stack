## 2. level_bridge.py pipeline spec (278 lines, mtime 2026-10-28 21:49)
1. Levelling: R_lv from mean LiDAR-IMU accel over first 1.0 s, rotated into FAST-LIO world; one-shot (IMU sub destroyed), never refreshed.
2. Pose per /Odometry stamp: p_lv = R_lv·p (LiDAR-IMU position), yaw = LiDAR forward axis projected on level plane; 50-entry exact-stamp cache; cloud dropped if no exact stamp.
3. Cloud /cloud_registered (FAST-LIO world, deskewed by FAST-LIO, point_filter_num 3) -> Q = R_lv·P - p_lv (level frame, origin at LiDAR IMU, floor ≈ -0.99 m).
4. Every 2nd cloud -> 5 Hz.
5. Height band: Z_MIN + 0.035·r_flat < z < Z_MAX (Z_MIN -0.65, Z_MAX 0.80 rel. IMU) ≈ 0.34+0.035r .. 1.79 m above floor. No ground segmentation, no intensity, no clustering, no temporal filter.
6. Marking (scan_obstacles): body frame via -yaw; 0.45 < r < 8.0; 1440 bins (0.25°); nearest in-band point per bin -> (x,y,0), frame base_footprint. NO FOV filter -> effective marking span = sensor span (bags: left to +52°, right to -58.8° at short range).
7. /scan = same per-bin minima (inf when empty), frame base_footprint. => /qazbot_lio/scan in bags is a faithful 2D record of what scan_obstacles marked (same bins, same ranges).
8. Clearing (clearing_endpoints): ALL points (not only band) with bearing in FIXED [-46.0°, +44.5°]; ray truncated where it exits the band (floor line or Z_MAX) and at range_max; per bin keep longest ray, cap just short of nearest in-band hit in that bin; drop if ≤0.45 m; output (x,y,0) base_footprint, marking=false.
9. Raytrace origin = base_footprint origin (sensor_frame ""), which is the LiDAR-IMU position re-labelled base_footprint: offset IMU vs native base_footprint not modelled (consistent for mark & clear; shifts the whole picture). TODO quantify offset.
Why [-46, +44.5]: D2 report 27.10 (docs/roadmap_v13/evidence/RPP_local_collision_20261027/20261027-rpp-local-collision-D2.md, review RPP-local-collision-review.md): "observed FOV" chosen as a FIXED mask because the data-driven 'seen' mask was never validated (D2 open item 1); raw span measured ±51.5° with vertical blind zone 0.5-0.7 m at |az| 45-50°. Never re-derived for the right edge (bags show marks to -58.8°).
Why the split / guarantee: D2 §4 + I1 (28.10): inf_is_valid on the 1440-bin scan would clear the unobserved rear/sides (inf_all wiped 239->15 lethal; rejected UNSAFE). Split guarantees (a) clearing only along rays physically observed in the current cloud, (b) never past the nearest in-band return of that bin, (c) a floor return cannot extend clearing beyond band exit, (d) unobserved bearings never cleared. It does NOT guarantee that every marked cell is clearable: marking span ≈ [-58.8, +52] vs clearing [-46, +44.5] -> mark-only sectors on both sides. D2 itself recorded this limitation ("the FOV-limited inf fix would NOT have prevented trial03") and chose BT ClearEntireCostmap as the mitigation — that is exactly the 10 s delay observed in D-04.
