## Что реализовано

- first_map с D1 перенесена; совместимость опубликованного occupancy grid проверена.
- Независимая локализация FAST-LIO + AMCL; вендорская лицензируемая локализация не используется.
- Полный Nav2: Smac2D, RPP, velocity smoother, BT ComputePathToPose/FollowPath.
- Публичный NavigateToPose и goal_pose для RViz через координатор владения целью.
  Координатор не планирует маршруты: это делает один внутренний Nav2.
- Проверки доверия локализации и адаптер X2 реализованы отдельно. Потеря доверия,
  операторский stop и обнаруженный конфликт источников закрывают командный контур.
- NavigateThroughPoses намеренно не поддерживается; восстановительные движения не включены.
- Код Teleworker не копировался. Два контейнера остаются целевой архитектурой,
  контейнерная миграция и интеграция центрального backend ещё не выполнены.

## Открытый дефект завершения Nav2

nav_restart_01: потеря контроллера, остановка группы и новая цель работали, но lifecycle
manager завис при shutdown. Кандидат candidates/nav2_lifecycle_shutdown переносит join
worker за инвалидирование ROS context (только standalone executable).
manager_rpc_after_01 подтвердил выход при замороженном контроллере; gdb attach запрещён
системой, backtrace этим тестом НЕ получен.

Однако nav_restart_02 выявил следующий дефект этого кандидата: все 11 функциональных
проверок положительны, но lifecycle manager завершился SIGABRT при создании таймера
после shutdown context. Кандидат НЕ принят и НЕ включён в обычный запуск.
Не обходить увеличением времени ожидания, отключением bond или подавлением исключения.

## Что ещё требуется до автономной навигации

1. Исправить и проверить shutdown lifecycle manager, включая зависший lifecycle RPC,
   потерю контроллера, обычный shutdown и повторный запуск; затем полный regression suite.
2. Принять реальную позу на карте и baseline доверия локализации по измеренным данным.
3. Измерить динамическую огибающую X2 и параметры управления/остановки на .66.
   Статический радиус 0.454 м и допуски модели не являются физической квалификацией.
4. Отдельно согласовать операторские испытания: SDK-регистрация, приоритет/перехват,
   cancel/stop, потеря данных, короткая цель, повторяемость с разных стартов.
5. Измерить ошибку достижения внешним средством; отчёт p50/p95/max позиции и угла.
   Обещание любой точки/любой исходной позы без локализации и проходимого пути невозможно.
6. Завершить модельные конфигурации D1/X2, общий стандартный API и контейнерные артефакты
   в принятой последовательности после физической приёмки.

ROS graph detection и локальный flock не доказывают атомарное владение аппаратным
каналом. Фактическое поведение приоритетов SDK/пульта требует испытания на роботе.

## Уточнение причины SIGABRT по gdb

nav_restart_03: reconnection false не устранил SIGABRT; исходная гипотеза о
respawn timer как непосредственном источнике опровергнута.
nav_restart_gdb_02: подтверждён stack Bond::~Bond → Bond::breakBond → abort при
очистке bond_map в checkBondConnections после инвалидирования context.
Следовательно, перенос join за shutdown без согласованного жизненного цикла bond
не является достаточным исправлением. Кандидат НЕ квалифицирован.

В debugger-run gdb возвращает 0 даже после SIGABRT inferior; его общий exit code
НЕ означает успешный тест. run_restart.py дополнен отдельной проверкой fatal signal
в debugger logs. nav_restart_gdb_01 остановился на SIGINT и не доказывает исправление;
nav_restart_gdb_02 дал нужный backtrace, но является отрицательным результатом.

## Завершение программной связки драйвера с Nav2

Подтверждён ранний перехват пультом, который core пропускал в пределах acquisition
grace: adapter_early_takeover_before.log — FAIL до правки; после правки все 37 unit OK.
Вход перенесён с cmd_vel на cmd_vel_authorized. Имя узла motion_adapter соответствует
подписке backend; run_x2_driver.sh задаёт namespace qazbot_d1_map и AimDK overlay.

Регистрация теперь один явный Trigger-запрос, без автоматических повторов и ENABLE
fallback. ACK code 0 создаёт MC publisher, но motion_armed остаётся false.
Новая публичная цель дополнительно вызывает motion_adapter/arm_motion.
Без SDK-регистрации, текущего trust/MC/TF, при latch и при незавершённой нулевой пачке
драйвер не разрешает команды. Resume не включает arm; перезапуск адаптера не должен
превращать продолжающийся поток старой цели в движение. Adapter status.ready — health;
он не равен разрешению отправлять скорости. Код не импортирует SDK в backend.

- nav_e2e_driver_unicast_01: 73 проверки, 0 failures, model/nav2 exits 0,

## Проверка гипотезы о высоте скана

meta.yaml D1 фиксирует laser_z=0.215 м. На X2 широкий slice начинается примерно
с 0.32 м и меняет минимальную высоту с дальностью. Это различие подтверждено.
По 50 сохранённым статическим raw clouds пол оценён в 0.970 м ниже IMU,
p95 residual 0.023 м; наклон 0.194°. Одометрия за окно изменилась до 0.0124 м.
Срезы около плоскости D1 дают меньше лучей и не обеспечили однозначно лучшего
совпадения: manual_amcl_turn_01_height_search.json содержит конкурирующие peaks.
Поэтому гипотеза НЕ признана доказанной корневой причиной и реальные scan/AMCL
параметры не изменены. Raycast конфликт может быть связан с различными высотами
видимости предметов; нельзя считать его доказательством неверной позы.
SciPy предупреждает о неподдерживаемой версии NumPy; предупреждение не скрыто,
пакеты среды не заменялись. Численные результаты диагностические.

Реальная S1-регистрация предложена оператору отдельным вопросом.
