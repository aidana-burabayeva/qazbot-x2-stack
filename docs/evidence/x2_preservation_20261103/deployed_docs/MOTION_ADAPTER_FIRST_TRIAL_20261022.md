# Motion Adapter: подготовка первого аппаратного испытания, 2026-10-22

Дополнение к X2_FIRST_PHYSICAL_TEST_PLAN.md, не замена плана и не разрешение
на аппаратные действия. Работа только с /home/agi/control_backend на .66.
FAST-LIO, Trust, affinity, работающий стек и исходники не изменялись.
Оператор подтвердил карту v3 и соответствие физической позы в RViz;
повторная глобальная локализация в этот сценарий не включена.

## Результат чтения кода и аппаратных результатов

- hardware_registration_01/result.json: один ADD sdk_qazbot_nav2, priority 30,
  ACK 0, SDK_velocity_messages=0, motion_arm_service_called=false, adapter_exit=0.
  Это аппаратное доказательство регистрации без скоростей, не ходьбы/остановки.
- В tests/footprint/data найдена только rest_standing_2026-10-21.npz:
  запись динамической огибающей там отсутствует.
- Подтверждённой численной скорости SDK на .66, тормозного пути и времени
  PS5 takeover в просмотренных аппаратных результатах не найдено.
  Значения с .89 и пределы speed_status их не заменяют.
- live=true сам не делает ADD. До ACK нет MC publisher; после ACK
  motion_armed=false и старая команда сбрасывается. Повторный ADD автоматически
  не выполнять: запись S1 могла сохраниться, GetCurrentInputSource сообщает
  только текущий источник, а не наличие всех зарегистрированных источников.
- Публичный /qazbot_d1_map/navigate_to_pose вызывает trust/arm_check и
  motion_adapter/arm_motion, затем открывает шлюз. Вручную arm_motion перед
  целью не требуется. Внутренний /qazbot_d1_map/nav2/navigate_to_pose не использовать.
- stop адаптера: motion_armed=false, latch; если был ACTIVE — 5 нулей на 50 Гц,
  затем тишина. Это выдача команд остановки, не доказательство физического
  торможения за 0.1 с. Watchdog входа — 0.15 с при controller_hz=20.
- После наблюдения своего источника смена на rc вызывает operator_takeover
  на ближайшем тике после получения McCommonState. До приобретения управления
  есть acquisition grace 0.5 с; если управление не получено — control_not_acquired.
  Это требует аппаратного измерения, обещания мгновенного takeover нет.
- resume адаптера снимает защёлку, но не arm. Координатор отдельно требует
  terminal старой цели, source_zero и текущий Trust; resume старую цель не ставит.
  Перезапуск адаптера начинает без регистрации и arm. Отсутствие автопродолжения
  проверяем на аппаратуре после конкретного stop/takeover.

## Скорости и ускорение: что нельзя принять за физическую квалификацию

nav_control.launch.py: defaults max_linear=0.3 м/с, max_angular=0.5 рад/с;
RPP min_approach_linear_velocity=0.12, approach_velocity_scaling_dist=0.6 м,
regulated_linear_scaling_min_speed=0.15. Поэтому весь маршрут 0.5 м находится
в зоне подхода: значение max_linear само по себе не задаёт скорость всего прохода.
Velocity smoother OPEN_LOOP: max_accel [0.4,0,1.0], max_decel [-0.6,0,-1.5],
max_velocity [max_linear,0,max_angular], reverse/lateral запрещены.
Это параметры исходника, не прочитанные параметры работающих узлов и не
измеренные безопасные значения MC. Перед live они сверяются с выбранным
профилем; малая команда может не вызвать шага. Не увеличивать её автоматически.

Прямой ros2 topic pub Twist в cmd_vel_authorized обходит goal_coordinator
и velocity_smoother; адаптер собственного slew limiter не имеет.
Для первой ходьбы этот путь не используем. Нормальная попытка идёт через
публичную цель Nav2 с smoother. stop/перехват — защитная остановка; её нулевая
пачка smoother обходит. Физическую устойчивость такой остановки надо измерить.

## Один короткий аппаратный цикл

0. Дождаться второго агента: FAST-LIO перезапущен, его адресный check завершён,
   независимая проверка опасных дефектов закончена. Никакого параллельного
   перезапуска стека и движения. Наши preparatory действия — только чтение.
1. На месте оператор подтверждает PS5 и штатный emergency stop, ровный пол,
   свободную полосу из существующего плана и огибающую рук/стоп. Нужна безопасная
   штатная страховка при необходимости; руками за движущиеся суставы не держать.
   Если динамический габарит отсутствует — использовать существующий F1,
   один короткий ручной проход с остановкой; отдельное согласие на движение.
   Не требовать поворотов и многодневной статистики для прямой первой попытки.
2. Отдельное согласие на замену dry-run адаптера одним live-адаптером, БЕЗ arm
   и движения. Остановить только согласованный dry-run PID; не killall/pkill.
   Координатор busy=false, gate=false, старая цель terminal. До запуска
   снять graph snapshot. Не оставлять два motion_adapter с одинаковым именем.
3. Проверить idle live: registration=not_requested, motion_armed=false,
   SDK publisher отсутствует; MC STAND (1), STABLE (4), source=rc. Проверить
   текущий speed mode и bounds штатным read_motion_state.py. Запуск live
   является отдельным согласуемым аппаратным действием, не выполнялся здесь.
4. Решить состояние предыдущего ADD; только затем отдельное согласие на один
   register. ACK проверяется по status registration=registered/error пустой,
   не по success Trigger (он означает лишь отправку запроса).
   Неудача ADD — стоп и разбор, без ENABLE fallback и повторов.
5. После ACK: idle, motion_armed=false, published=0, MC source=rc,
   foreign_publishers=[], один наш MC publisher. Граф фиксирует владельцев;
   четыре вендорских издателя сами по себе не конфликт. Source=pnc,
   неизвестный SDK или лишний автономный издатель — движение не начинать.
6. Если подтверждённой SDK-скорости нет, сначала согласовать ОДИН кандидатный
   профиль из S3 существующего плана и отдельную короткую попытку. Это измерение
   порога страгивания, не уже квалифицированная скорость. Числа 0.10/0.15/0.20
   из старого плана не выполняются серией. Через публичную цель, с smoother,
   операторский stop примерно через 1 с после первой ненулевой MC-команды
   или раньше при рывке/нестабильности/смещении около 0.2 м. Время оператора
   и отметка расстояния не являются автоматическим ограничителем перемещения.
   Для этого шага нужны страховка и достаточное пространство с запасом на
   неизвестный тормозной путь. Если безопасно провести нельзя — не выполнять.
   Если шага нет — остановка, разбор, без следующей скорости автоматически.
7. После разбора первого импульса отдельно согласовать PS5 takeover (S4):
   та же уже проверенная скорость, короткий участок, оператор касается стика
   после подтверждения MC source=sdk_qazbot_nav2. Зафиксировать переход rc,
   latch=operator_takeover, motion_armed=false, нули и отсутствие возврата
   SDK-движения после отпускания стика. Не делать resume автоматически.
8. После подтверждения скорости, stop и takeover — отдельное разрешение на N1:
   одна публичная цель 0.5 м прямо, ориентация сохранена, допустимый профиль
   скорости/ускорения и достаточная огибающая зафиксированы ДО отправки.
   Допуск 0.10 м/0.10 рад — предложение существующего плана, согласуется заранее.
   Политика rotate_to_heading сейчас включена: перед попыткой путь должен
   действительно идти вперёд; неожиданный поворот/изгиб — отказ от запуска.
   Первую цель не совмещать с отменой посередине: остановку проверяем предыдущим
   отдельным шагом. Следующая цель/возврат только после разбора и нового согласия.

## Команды операторского сценария (НЕ выполнялись)

Окружение в каждом терминале:
```bash
cd /home/agi/control_backend
source ws/src/navigation/env.sh
source ws/src/navigation/aimdk_env.sh
```

Read-only перед согласованным live-шагом (последовательно):
```bash
python3 ws/src/navigation/read_motion_state.py
python3 tests/nav_e2e/live_graph_snapshot.py tests/integration_results/ADAPTER_TRIAL_BEFORE.json
```

После согласованной остановки dry-run адаптера, отдельного разрешения live,
проверки отсутствия второго экземпляра и паузы между запусками >=2 с:
```bash
bash ws/src/navigation/run_x2_driver.sh -p live:=true -p priority:=30
```

Только после отдельного решения по старому ADD и разрешения register:
```bash
ros2 service call /qazbot_d1_map/motion_adapter/register std_srvs/srv/Trigger '{}'
```

Два независимых программных stop в заранее открытых терминалах:
```bash
ros2 service call /qazbot_d1_map/goal_coordinator/stop std_srvs/srv/Trigger '{}'
ros2 service call /qazbot_d1_map/motion_adapter/stop std_srvs/srv/Trigger '{}'
```
При опасном поведении сначала PS5/штатный emergency stop, не ждать ROS CLI.
Не рассчитывать на SSH как на единственный путь остановки. Не выполнять
resume автоматически. После остановки сначала подтвердить физическую тишину.

Одна штатная bag-запись вместо новых тестовых компонентов; без raw cloud:
```bash
ros2 bag record -o logs/adapter_trial_UNIQUE \
 /aima/mc/common/state /aima/mc/locomotion/velocity \
 /qazbot_d1_map/cmd_vel /qazbot_d1_map/cmd_vel_authorized \
 /qazbot_d1_map/motion_adapter/status /qazbot_d1_map/goal_coordinator/status \
 /qazbot_d1_map/localization_trust/status /qazbot_d1_map/amcl_pose \
 /qazbot_d1_map/tf /qazbot_lio/odom_level /aima/mc/leg_odometry
```
Завершить recorder Ctrl-C после остановки робота; анализировать только закрытый
bag с metadata.yaml. Запись содержит IMU-проекцию odom и MC, но не является
внешней эталонной траекторией. Старт/финиш измеряются рулеткой.

Цель: xg=x0+0.5*cos(yaw0), yg=y0+0.5*sin(yaw0),
qz=sin(yaw0/2), qw=cos(yaw0/2). Подставить проверенные численные значения
и показать оператору ПЕРЕД разрешением. Никаких старых координат B или goal3.
После этого команда ровно одна:
```text
ros2 action send_goal /qazbot_d1_map/navigate_to_pose nav2_msgs/action/NavigateToPose
  '{pose: {header: {frame_id: map}, pose: {position: {x: XG, y: YG, z: 0.0},
    orientation: {x: 0.0, y: 0.0, z: QZ, w: QW}}}}' --feedback
```
Здесь XG/YG/QZ/QW — незаполненный шаблон, НЕ готовая команда движения.
До получения скорости/позы/условий безопасности численную команду не выдавать.
