# Допуск локализации: сравнение с local_control_system_py, 2026-10-22

Это предложение и независимая адресная проверка. Production-код, процессы,
параметры и допуски робота в этой сессии не изменялись. Команд движения нет.
Согласно актуальному .orchestrator/DECISIONS.md robot owner — сессия agi-f9;
эта сессия не выполняет аппаратные команды и не дублирует T5-правку.

## Что подтверждено в локальном референсе
Исходник:
local_control_system_py/ws/src/teleworker_localise_actions/src/teleworker_localise_actions_server.py
публикует операторскую initialpose с default cov_xy=0.25 м² (sigma=0.5 м),
cov_yaw=0.0685 рад². На той же карте action завершается после публикации
и штатного clear costmaps; ожидания sigma_xy<0.2 в этом пути нет.
teleworker_status/src/teleworker_navigate_to_pose.py передаёт цель одному Nav2.
teleworker_action_common/teleworker_action_common/action_guard.py проверяет
hw_fault, занятость, владение задачей. В просмотренном пути нет нашего
скользящего критерия накопления 0.1 м коррекции за секунду.
Это вывод о просмотренных исходниках, не доказательство полной безопасности
Teleworker и не основание копировать его код или параметры платформы.

## Предлагаемая политика
1. Операторская инициализация/подтверждение позы и текущая карта — отдельное
   осознанное commissioning-событие. Не объявлять sigma=0.27 или 0.5
   измеренной ошибкой позиции. sigma_xy<0.2 — наша кандидатная политика,
   не обязательное требование стандартного Nav2/AMCL.
2. После принятого READY ковариация/облако/scan-score — диагностика качества;
   нормальные последовательные поправки AMCL не должны стирать READY.
   Свежесть критических данных, корректность карты, управление MC, PS5,
   единственный владелец и отсутствие автопродолжения остаются защитами.
3. Не менять одновременно стартовую политику и T5. Ближайшее одно изменение —
   корректный детектор разового разрыва; начальный допуск обсуждается отдельно
   при фактическом отказе его конкретного условия. Операторское подтверждение
   не является обещанием абсолютной точности, а covariance не является её
   независимым измерением. Рулетка не обязательная часть штатного AMCL.

## T5: предложение верно по смыслу, реализация пока неполна
На .66 loc_trust.py уже изменён другим агентом: сравнение соседних значений
вместо окна 1 с; пороги XY=0.10 м, yaw=0.10 рад сохранены.
Отчёт .orchestrator/...-t5step.md: на short_nav_01 max per-update 0.066 м,
старый критерий срабатывает, новый при tick replay не срабатывает.
Это одна запись; плавный ошибочный дрейф новый критерий по определению
не обнаруживает, нельзя утверждать, что он ловит всякую ложную локализацию.

Критический пробел: TrustNode._tf перезаписывает self.mo при каждом сообщении,
а evaluate читает последнее значение раз в 0.2 с. Сравнение на evaluate-тиках
НЕ гарантирует сравнение всех соседних входных обновлений. Независимый probe:
реальный TrustNode._tf получил 0.5 м, затем 0 м до следующего тика;
реальный evaluator получил 0 м, jump_xy=0, READY=true.
Доказательство: tests/integration_results/t5step_independent_review_01.json.
ROS init не вызывался, узлы и издатели не создавались. Probe проверяет именно
потерю промежуточного события, не весь safety contract.
При импорте показано существующее предупреждение NumPy/SciPy; пакеты не менялись.

Минимальное исправление для владельца реализации:
- считать delta на каждом принятом валидном update map→odom, не на каждом тике;
- при превышении существующего порога сохранить факт нарушения до его обработки,
  даже если следующее сообщение вернулось обратно;
- через stale/invalid gap сравнивать первый свежий update с последним валидным;
- после отказа прежняя цель не возобновляется; требование нового допуска сохраняется.
Не сравнивать просто соседние amcl_pose: в них есть нормальное движение робота.
Для начального сообщения без пары не выдумывать нулевую предыдущую позу.
Транспортные повторы не являются новым физическим скачком.

Адресные проверки перед включением:
плавные 6x0.06 без отказа; одиночные 0.15/0.5 с отказом; yaw wrap;
gap с разрывом и без; два сообщения 0→0.5→0 между тиками с сохранённым отказом;
повторное поступление нормальных данных не возобновляет старую цель.
Полный Nav2/model suite ради этого не нужен. Сначала этот короткий набор
и независимая проверка, затем один отдельно разрешённый физический возврат
при операторе с PS5 и согласованном свободном маршруте. Достижение цели
проверяется физически; смена алгоритма сама по себе не является приёмкой.
