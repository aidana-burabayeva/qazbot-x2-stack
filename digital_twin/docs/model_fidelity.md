# Достоверность модели (что twin доказывает, а что нет)

| Вопрос | Ответ |
|---|---|
| Это тот же стек, что на роботе? | Да: те же файлы `ws/src/navigation`, те же аргументы запуска, те же имена топиков. Версии Nav2: 1.1.20 в twin, 1.1.18 на роботе |
| Это тот же MC? | **Нет.** sim: `mc v1.0.0-20260522`; робот: `mc v1.1.0-r9-rc9` (mc_param v1.1.0-r9-rc3). Параметры локомоции идентичны (`foundationwalk_v1.onnx`, PD, пороги); код раннеров различается — влияние не проверено |
| Воспроизводятся ли Блокеры? | Качественно: Блокер 1 (срыв разворота на месте при ±0,5 рад/с, `Failed to make progress`) и Блокер 2 (перелёт, эффективная минимальная скорость ~0,45 м/с). Количественно не калибровано |
| Одометрия | истина MuJoCo (таз), не LIO: нет дрейфа и артефактов LIO; точка отслеживания — таз, а не IMU груди (~0,1 м) |
| Скан | ray-cast по карте от истинной позы: по умолчанию передний сектор **~103°**, 1440 бинов по кругу (вне сектора `inf`, не «свободно»), 5 Гц, 0,45–8 м — параметры наблюдений .66 и `x2.yaml` (`scan_fov_deg: 360` для идеализированного кругового). Всё ещё идеальные лучи от таза: нет облака, вертикальной фильтрации, дрейфа LIO и реальной разреженности. По умолчанию MuJoCo получает **физические стены** из занятых клеток той же карты (`TWIN_WORLD=map`): робот сталкивается ровно с тем, что есть в карте; неизвестное не «твёрдое». `TWIN_WORLD=flat` — пустой пол вендора |
| Динамика в лёгком режиме | идеализирована, константы из документации AimDK, не откалибрована |
| Доказывает ли успех в sim исправность робота? | **Нет.** Это инструмент сравнения вариантов до физической пробы |
Подробные измерения и сравнения с реальными bag: `control_backend/docs/digital_twin/` (`official_mc_chain_20261026.md`,
`leg_vs_lio_20261026.md`, `20261023-twin-mcparam-diff.md`, `friday_data_review.md`).

## Наблюдения параллельного сеанса (26.10), вошедшие в оценку
Источник: `control_backend/docs/digital_twin/interactive_rviz_20261026.md` (скрипты в `tools/twin/`, не перенесены в этот проект).
- Официальный MC v1.0.0 в мире со стенами: «туда» SUCCEEDED с перелётом ≈0,19 м, «обратно» ABORTED из-за отсутствия прогресса при развороте (в согласии с `official_mc_chain_20261026.md`).
- Команда −0,5 рад/с после ходьбы: итоговый поворот −78,6°, скорость последних 4 с ≈0. Непрерывные ±0,8 рад/с (по одной пробе в сторону) поддерживали вращение ≥12 с (−761,6° / +814,5°), но фактическая скорость ≠ заданной (≈1,08 / 1,24 рад/с). Это **не** устанавливает порог MC и не годится как предел для .66 (там v1.1.0-r9-rc9; любые изменения движения — только после проверки на роботе с подтверждением оператора).
- Политика допуска Trust по умолчанию теперь `go2` (с автозапросом AMCL после начальной позы): twin больше не навязывает `strict`, а следует умолчанию стека (`trust_policy:=` пусто).
