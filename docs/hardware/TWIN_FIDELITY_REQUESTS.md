# Twin fidelity requests (данные, нужные с физического X2)

Статус каждого пункта `NEEDS_HARDWARE`, пока нет замера. Источник: расхождения и допущения симуляции (`lab_robot_state.json`). Не подгонять twin под один сценарий.

## FID-01. Frame-contract: привязка plant/world <-> карта Nav2 (ПЕРВОПРИЧИНА УСТАНОВЛЕНА в симуляции)

- Что уточняет: В симуляции причина доказана (FrameAligner привязывается к первому сэмплу, а стены — к номинальному спавну; после подъёма робот оседает с yaw +0.108 рад). Для робота это НЕ причина (там map->odom ведёт AMCL/T5), но нужен независимый эталон позы, чтобы проверить, что карта и реальный мир согласованы
- Замеры: Поза робота в map (AMCL) и независимая поза (рулетка/метки) в 4–6 точках, включая проём; плюс yaw-ориентация по лазерной метке/стене. Данных для этого в бэгах НЕТ (там только AMCL/одометрия)
- Topics / TF / параметры / логи: /tf, /tf_static, /amcl_pose, /map metadata (origin, resolution), sha256 map.pgm
- Условия воспроизведения: Статичное положение в каждой точке 10 с; одна и та же карта main_office
- Движение робота: Да — перестановка робота оператором между точками (автономного движения не требуется)
- Ожидаемая точность: ±0.02 м по рулетке/меткам
- Сопоставление robot ↔ twin: Те же точки в twin по world pose; сравнить dxy на каждой точке
- Статус: NEEDS_HARDWARE

## FID-02. Отклик MC на команду поворота на месте (yaw)

- Что уточняет: Модель MC/MuJoCo воспроизводит stall (wz команда без поворота) иначе, чем реальный MC
- Замеры: wz команда vs измеренный yaw-rate, 0.2/0.4/0.6 рад/с, оба направления, от нуля и после ходьбы
- Topics / TF / параметры / логи: /cmd_vel_authorized, одометрия торса/IMU, MC status, bag lossless
- Условия воспроизведения: Пустое открытое место, ровный пол, батарея >50%, одно и то же ПО
- Движение робота: Да — требуется явное разрешение оператора
- Ожидаемая точность: yaw-rate ±0.02 рад/с, тайминг ±20 мс
- Сопоставление robot ↔ twin: Тот же профиль команд в twin; сравнить rise time, steady-state, coast
- Статус: NEEDS_HARDWARE

- Topics / TF / параметры / логи: одометрия, TF, видео/метки для внешней позы
- Условия воспроизведения: Те же, что выше
- Движение робота: Да — требуется явное разрешение оператора
- Ожидаемая точность: ±0.02 м, ±0.02 рад
- Сопоставление robot ↔ twin: Сравнение распределений по 5 повторам, не по одному прогону
- Статус: NEEDS_HARDWARE

## FID-06. MC: насыщение скорости и выбег — сравнить реальные ответы с twin (данные УЖЕ получены, нужен только replay в sim)

- Что уточняет: Реальный MC: команда vx=0.8 даёт ~0.45 м/с (насыщение); команда 0.2–0.3 даёт 0.24–0.43 м/с по native_odom (превышение до 1.4×); выбег 0.04–0.17 м за 2 с; yaw-отклик 0.67 -> 0.59 рад/с. Модель MC/MuJoCo в twin может вести себя иначе
- Замеры: Ступенчатые команды vx = 0.1/0.2/0.3/0.45/0.6/0.8 и wz = ±0.2/±0.4/±0.67, по 3 повтора, оба знака; записывать /aima/mc/locomotion/velocity, /aima/mc/leg_odometry, /qazbot_native/odom, /aima/mc/body_pose с внешним эталоном (метки/рулетка на 3 м пробеге)
- Topics / TF / параметры / логи: docs/evidence/robot_20261030/real_mc_response_summary.json (7 серий из бэгов); сырые бэги в robot_data (sha256 в summary)
- Условия воспроизведения: Ровный пол, свободные 6 м, батарея >50%, тот же софт (platform v1.1.5, aimdk_msgs v1.1.0.4)
- Движение робота: Да — только с явным разрешением оператора; существующие серии записаны во время ab_eval_motion
- Ожидаемая точность: скорость ±0.02 м/с, путь ±0.02 м, yaw ±0.02 рад
- Сопоставление robot ↔ twin: Те же профили команд в twin; сравнить steady-state ratio, rise time, coast на тех же 7 сериях (первый шаг не требует робота)
- Статус: NEEDS_HARDWARE

## FID-07. Время и свежесть данных: map->odom опережает приём на ~0.95 с; скан устаревает под нагрузкой

- Что уточняет: AMCL датирует map->odom вперёд на transform_tolerance (1.0 с по умолчанию): stamp - rx p50 = +0.95 с. Под нагрузкой (load ~18) scan age p95 0.6–1.9 с, T1_scan_stale 0.11–0.25. Twin работает с идеальными таймингами
- Замеры: Повторить замер age(scan), age(odom), lag(tf) при нагрузке стека, покоя и ходьбы; записать load1/CPU
- Topics / TF / параметры / логи: docs/evidence/robot_20261030/topic_selection.txt, tf_tree.txt; recorder_events.log и monitor.csv на роботе (docs/evidence/twin_20261030)
- Условия воспроизведения: Тот же стек, recorder выключен в контрольном окне; без движения и с движением
- Движение робота: Нет для покоя; да для ходьбы (с разрешением)
- Ожидаемая точность: ±5 мс
- Сопоставление robot ↔ twin: Добавить в twin инжекцию задержки/дрожания сканов по измеренным распределениям, проверять T1/T5 на тех же p50/p95
- Статус: NEEDS_HARDWARE
