# Навигация по случайным целям: продолжение 27 октября

Исследования находятся в `digital_twin/research`, реальный стек — в `control_backend/ws`, подключённом относительной ссылкой. Перед пересозданием четырёх старых контейнеров сохранены их writable layers; идентификаторы и diff — в `runtime_x86/container_preservation_20261027`. Для навигации используются отдельные `qazbot-nav-research-20261027` и `qazbot-nav-research-b-20261027`, network none / IPC private. Эксперименты с MC в других контейнерах не останавливались.

## Условия и критерий

Кинематический стенд, настоящие AMCL, Trust, Coordinator, Nav2, адаптер и виртуальный MC. Карта v3, фронтальный обзор 103°, 5 Гц; задних и боковых измерений нет. Одометрия идеальна, лучи идеальны и исходят из таза: точность реальной LIO и механика MC здесь не проверяются. На .66 изменения не устанавливались, команды движения не отправлялись.

Сохранённая выборка `tests/integration_results/random_accuracy01/targets.json`, seed 20261026: восемь известных свободных достижимых точек с запасом для тела, чередование открытых мест и границ, случайное направление. Успех требует завершения обоих действий и **истинной** ошибки в каждой конечной точке не более 10 см / 0,10 рад. Внутренний Nav2 использует более строгие 5 см / 0,06 рад и требует остановки. Ground truth применяется только к оценке результата.

## Найденные причины и изменения

1. Обычный RPP около XY-порога переключался между поворотом к маленькому вектору смещения и поворотом к конечному yaw. Кандидат `candidates/nav2_pose_refine` сохраняет фазу выравнивания при перепланировании той же цели. Оставшаяся после yaw короткая XY-поправка выполняется RPP к зафиксированной точке в `odom`; затем вновь проверяется цель в карте. Обхода ограничений движения или проверок столкновения нет.
2. Smac 1.1.20 в ветке «старт и цель в одной клетке» возвращал координаты старта вместо запрошенной цели. Кандидат `candidates/nav2_exact_goal/goal_endpoint.patch` сохраняет точный конец маршрута. Обычный конец в достигнутой целевой клетке также уточняется до запрошенного XY. Существующая bounds-проверка сохранена.
3. Приём TF в Trust мог ждать mutex диагностического вычисления. Приём выделен в отдельный executor, map-поправки складываются в очередь и все применяются при следующей оценке. Пороги свежести и проверки source stamp не ослаблены.
4. Холодный запуск lifecycle мог потерять первый ответ DDS. Стенд сначала ждёт готовности manager и обнаружения ответов, затем явно запускает lifecycle. Production autostart остаётся прежним.

AMCL `likelihood_field_prob` / 1440 выбран по сравнению на одинаковой записи идеального фронтального скана. Это кандидат для стенда; перенос sensor model на .66 требует реальных облаков. Production AMCL не заменён.

## Отдельные проверки

- `exact_goal_candidate_checks01`: шесть фактических ComputePathToPose с некратными клетке координатами, ошибка конца XY/yaw = 0; обе цели вне карты отклонены, последующая корректная цель обработана. В baseline шесть ошибок конца 2–5,7 см. Команд движения не было.
- `trust_ingress_20261027_01`: при удержании evaluator mutex 1 с приём продолжился; возраст odom 0,020 с, odom message 0,100 с, scan 0,200 с, map TF 0,200 с. Сохранены восемь map-поправок. После прекращения потока на 0,8 с обнаружена настоящая просрочка. Probe не имеет motion publisher.
- `exact_goal_target3_04`: прежде зацикливавшаяся цель №3 пройдена; истинная ошибка у цели **5,41 см / 0,0353 рад**, дома **3,12 см / 0,0303 рад**, все дочерние процессы завершились с кодом 0.
- 13 выбранных unit tests watchdog, sensor model, dwell и process exit audit прошли. Полный pytest по `tests/twin` не запускался: четыре файла являются исполняемыми сценариями.

## Серии

Baseline `random_batch01`: 5/8. Промежуточный `random_fixed_batch01`: 7/8, цель №3 не завершила выравнивание; успешные выезды 0,18–7,31 см, возвраты 2,49–3,32 см. Это независимые поездки со стартовой инициализацией перед каждой, а не непрерывная серия без reseed.

Новая серия `random_exact_20261027_01`: **1/8**, единственная полностью успешная поездка №8. Поездки №1–6 остановились на выезде по просрочке входных данных; №7 дошла до цели, но остановилась на возврате по `T1_odom_stale`. Все остановки и неудачи сохранены. Это регрессия устойчивости стенда; успех отдельной цели №3 не доказывает исправление всей выборки. Источник задержек пока не установлен.

Дополнительные неуспешные диагностические пробы: `exact_scan_health27_01`, `exact_ingress_diag27_01`, `exact_udp_diag27_01`, `exact_executor_diag27_01`, `exact_shm_diag27_01`, `exact_udp_large27_01`, `exact_reliable_scan27_01`. Генерация скана занимала 16–41 мс, публикации продолжались примерно каждые 200 мс; Trust иногда видел источник старше 0,5 с. Измеренные callback durations в Trust были малы. UDP-only, один executor с тремя потоками, увеличение `/dev/shm` до 1 ГБ и Reliable-приём скана не обеспечили успешную поездку. У SHM-пробы был отказ lifecycle ещё до движения. Ни один из этих вариантов не принят как исправление. Один executor и Reliable-приём скана откатили; default транспорта прежний, экспериментальный UDP-only остаётся явным флагом. Лимит SHM по умолчанию сохранён 64 МБ, для воспроизводимости доступен `QAZBOT_TWIN_SHM_SIZE`.

После диагностических изменений: выбранные тесты политики Go2, seed refresh, source failures и gaps — **54 passed, 2 skipped** (ROS-зависимые проверки недоступны на хосте). Контейнеры на момент остановки работы не запущены; RViz не открыт. Новая схема уточнения цели остаётся кандидатом, не настройкой по умолчанию. Дальше необходимо локализовать задержку от source stamp до callback и лишь затем повторить все восемь целей и непрерывную серию без reseed.
