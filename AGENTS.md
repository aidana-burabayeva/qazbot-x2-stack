# QazBot X2: правила продолжения работы

Сначала прочитайте [docs/HANDOFF.md](docs/HANDOFF.md) и [docs/TEST_STATUS.md](docs/TEST_STATUS.md). Это передача текущего состояния, а не предложение нового аудита.

Текущий приоритет: первый безопасный физический NavigateToPose через RViz. Порядок: T5 LIVE → I1 E2E → I1 REVIEW → отдельно разрешённый I1 DEPLOYMENT → отдельно разрешённый RViz Goal → устранение измеренной причины ABORTED → устойчивый SUCCEEDED. Небольшие ошибки движения допустимы, если маршрут безопасен; не требовать идеальной сантиметровой точности. Не ослаблять collision detection, реальный footprint, T5 и freshness protections.

## Источники истины и архитектура

- Репозиторий: https://github.com/aidana-burabayeva/qazbot-x2-stack; production baseline: main, c15dd6c6c8fe8d5e6cc1014c68bb9da51dd8a3fa.
- ROS 2 Humble; X2: agi@192.168.1.72. Пароли не сохранять в репозитории.
- Локальный репозиторий: /home/adn/QazBot/control_backend; production-код относительно корня репозитория: ws/src/.
- Digital Twin расположен отдельно: /home/adn/QazBot/digital_twin/. Если он недоступен, сообщить; не восстанавливать отсутствующий код по догадкам.
- D1 создаёт единую 2D-карту; X2 использует AMCL и Nav2, 3D LiDAR преобразуется в LaserScan. Постоянная 3D-карта не планируется.
- Штатная одометрия через native_odom_bridge владеет odom → base_footprint. AMCL единолично владеет map → odom. В localization native_imu level_bridge запускается с publish_tf:=false.
- FAST-LIO готовит облако; Motion Adapter управляет через AIMDK/MC; Localization Trust контролирует локализацию.
- Не менять архитектуру, не заменять AMCL на Beluga, не удалять FAST-LIO, не менять alpha-параметры без измерений.

## Физический робот

- Только один владелец робота. Каждую новую сессию начинать с read-only проверки процессов, владельцев, ROS topics и источников TF; старые PID и логи не доказывают текущее состояние.
- Не запускать дубликаты FAST-LIO, AMCL, Trust, level_bridge. Не останавливать чужие процессы. Linux-пользователь agi и тег сессии сами по себе не доказывают передачу владения.
- Без отдельного разрешения не менять production-код X2; не запускать MC, Motion Adapter, Goal Coordinator; не отправлять cmd_vel или Nav2 goals.
- Движение требует проверки актуального состояния, присутствия оператора, рабочего RC/останова и явного разрешения.
- Initialpose задаёт оператор через RViz после подтверждения фактической позы. Координаты не угадывать.
- После теста останавливать только процессы, принадлежащие этой сессии, и проверять освобождение ресурсов.
- Для записи PointCloud2 нужно отдельное разрешение после завершения T5 LIVE. Запись пассивная, без MC и движения. Перед согласованным запуском сенсорного стека проверить отсутствие действующего экземпляра.
- Новый DDS-участник ранее задерживал FAST-LIO: минимизировать наблюдателей, фиксировать влияние.

## T5 и I1

- T5 уже установлен и SHA256 подтверждён. Не переустанавливать. Пороги 0.10 м / 0.10 рад не менять.
- T5 сравнивает смещение робота при двух коррекциях map → odom в одной odom-позе, а не translation трансформа.
- I1 вести отдельно: ветка fix/i1-rpp-collision, worktree /home/adn/QazBot/control_backend_i1. Пока T5 LIVE не завершён, I1 выполнять только на ПК.
- Не копировать целиком старый digital_twin/candidates/i1_rpp_collision/level_bridge.py: он потеряет production-изменения TF/native odometry. Переносить минимальный diff на актуальный ws/src/lio/level_bridge.py.
- Наличие точки пола на 1 м не доказывает свободный луч до 3.5 м. Азимутальное покрытие и его dilation не являются подтверждением свободной дальности.
- Не объявлять неизвестную зону свободной. Настоящие препятствия должны сохраняться.
- Обязательны unit tests, фактический Nav2 ObstacleLayer regression, повтор I1 A/B и проверка на сохранённом реальном /qazbot_lio/cloud_registered. Сырые lidar_pointcloud не заменяют этот вход.
- Запрещены ClearEntireCostmap, магические таймауты/retries и отключение collision detection.
- I1 на робот автоматически не устанавливать. T5 и I1 в один коммит не смешивать.
- Потерянный хвост First_RViz_goal_1135 невосстановим: использовать имеющиеся альтернативные реальные проверки, явно сохраняя ограничение.

## Документирование

Проверить HEAD, git status обоих worktree и наличие нужных файлов. Сохранять чужие незакоммиченные изменения. Документировать новые результаты с датой, средой и доказательствами; исторические результаты не называть новыми прогонами. Обновлять HANDOFF и TEST_STATUS при смене состояния. Не ставить LIVE PASS или I1 READY без требуемых измерений.

Перед завершением сессии публиковать необходимые коммиты в отдельной ветке. Незакоммиченный файл не должен быть единственной копией результата. Поддерживать краткий CLAUDE.md, отсылающий к этим правилам и HANDOFF. Секреты и runtime не загружать в Git. Новое прямое указание оператора: сами bags и логи робота публиковать в GitHub под docs/evidence, с manifest и SHA256; разрешено lossless сжатие. Сырые производные .db3 остаются игнорируемыми, в Git хранится восстанавливаемый .db3.gz и metadata.yaml. Для core/runtime указывать проверенные внешние пути и SHA256. Новый агент начинает с опубликованного Git SHA, а не с восстановления по памяти.

На X2 /home/agi/control_backend является deployed-каталогом без .git. Не выполнять git init поверх него и не заменять runtime клоном. Git-работа ведётся в настоящем checkout на ПК либо в отдельно подготовленном checkout; установленную версию X2 проверять по deployment manifest/целевым SHA256, не выдавая отсутствие .git за повреждённый репозиторий.
