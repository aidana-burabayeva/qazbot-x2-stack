# I1 — ложный «RPP detected collision ahead» (цифровой двойник), 27–28.10.2026

Цикл правила: **блокер** → **референс** → **эксперимент** → **решение**.
- Блокер: Goal01 на физическом X2 (`control_backend/docs/roadmap_v13/RVIZ-goal01-result.md`, `RPP-local-collision-review.md`): устаревшие lethal-клетки local costmap, которые скан не очищает; RPP отказывает цели без движения.
- Референс: диагностика и предложенный патч из `RPP-local-collision-review.md` + реплей D2 (`evidence/RPP_local_collision_20261027/`). Кандидат `candidates_v13/I1_rpp_collision/` лежит на роботе, в сеансе недоступном по сети: патч восстановлен по описанию отчёта.
- Решение: **ADAPT** (пп. 1–2 отчёта, критерий «наблюдаемо» уточнён, см. ниже). П. 3 отчёта (BT с `ClearEntireCostmap` и retries) НЕ делается по условию задачи.

## Патч (`candidates/i1_rpp_collision/level_bridge.patch`)
1. `level_bridge`: ячейка скана = ближайший возврат (finite) / `+inf` = **наблюдаемо свободно** / NaN = неизвестно.
   `+inf` ставится, только если одновременно: бин внутри маски FOV (−46…+44,5°), в этом азимуте сенсор выдал **хоть какую-то точку** (пол, дальняя стена: покрытие считается по ВСЕМ точкам облака до среза по высоте и дальности, щели между лучами ≤3 бин сшиваются), и бин не ближе ±2 бин к реальному возврату. Нет покрытия (лидар мёртв, сектор закрыт, поглощающая поверхность) → NaN, т.е. ничего не очищается. Без параметра покрытия `+inf` не создаётся вовсе.
   Эвристический порог «≥20 бин с возвратами» из первой редакции **убран**: «мало возвратов» не признак отказа (в открытом зале лидар нормально видит почти ничего в срезе), признак отказа — отсутствие точек в азимуте.
2. Local costmap: `obstacle_layer.scan.inf_is_valid: true` (NaN игнорируется, `+inf` очищает луч до `range_max`). `raytrace_max_range 3.5`, `obstacle_max_range 3.0`, radius 0.454, padding 0.01, `use_collision_detection`, `failure_tolerance` без изменений.
Не затронуто: footprint, collision detection RPP; нет `ClearEntireCostmap`, retries, увеличения таймаутов. Физический X2 и `control_backend` не менялись (в twin-образе правится только копия `nav_control.launch.py`, переключатель `QAZBOT_I1_INF_VALID`, по умолчанию выключен).

## Проверки
**Юнит-тесты** (`make test-i1`, контейнер dev): 42 passed, flake8 чист. Среди них граничные случаи порога/покрытия:
- 19, 20, 21 (и 0, 1, 22, 100, 400) возвратов **без покрытия** → `+inf` нет ни при каком количестве;
- те же 19/20/21 возвратов **с покрытием** → все свободные бины очищаются одинаково, «обрыва» на 20 нет; больше возвратов может только убрать `+inf`, не добавить;
- половина сенсора закрыта → закрытая половина остаётся неизвестной;
- свойство на 200 случайных сценах: `+inf` только внутри FOV, только на покрытых бинах и не на бинах с возвратом.
**Реальные сохранённые облака физического X2** (`scripts/i1/real_cloud_check.py`, стоя 75 облаков, в ходьбе 72 облака; срез как в bridge):
- C1 ни один настоящий возврат не потерян/не изменён; C2/C3 `+inf` нигде вне FOV и рядом с возвратом; C4 каждый `+inf` лежит на покрытом азимуте; C5 при удалении всех точек половины FOV `+inf` там нет (кроме сшивки ≤3 бин у границы): 0 нарушений везде;
- сколько бин с возвратами в FOV на облако: стоя min 218 / медиана 223, в ходьбе min 200 / медиана 203 (порог 20 был бы на порядок ниже любого реального облака, но он и не нужен);
- доля свободных бин FOV, оставшихся неизвестными из-за отсутствия покрытия: 0,0 (правило покрытия не ограничивает лишнего на сырых облаках). Оговорка: проверено на сырых облаках `lidar_pointcloud`; bridge получает прореженные `/cloud_registered` (FAST-LIO `point_filter_num=3`), в bag их нет. Если там покрытие окажется реже, свободное чаще останется неизвестным (безопасная сторона), `cover_dilate_bins` настраивается.
**Реплей D2** на записанных сканах (из отчёта, не перезапускался): Goal01 при маске FOV свободен по всем 5 проверкам v=0,3; синтетическое препятствие 0,6–0,8 м остаётся lethal 48/48.

## Twin A/B (`make scenario-i1 TAG=x`, `scripts/i1/run_series.sh`)
Одинаковые условия, truth-локализация, старт −7,3; 4,6; −20°. Цепочка команда → plant → LaserScan → ObstacleLayer → costmap → Nav2/RPP доказывается по состояниям: команда публикуется **один раз** с `seq`, plant подтверждает применённое состояние (нет подтверждения = ошибка доставки, не повтор); скан читается после подтверждения; lethal ищется на ожидаемой поверхности диска, не в его центре.
Фазы: A настоящее препятствие; C потеря скана (нет сообщений / пустой скан / закрыт сектор); B препятствие убрано, скан читает «свободно»; D препятствие за краем маски; E свободный маршрут.
| Серия | сектор плант-скана | baseline воспроизводит баг | кандидат: все проверки A–E | «collision ahead» E: baseline / кандидат |
|---|---|---|---|---|
| r1 | 130° | да | да | 7 / 0 |
| r2 (baseline перезапущен как r2b: первый запуск остановился на предусловии геометрии — за краем маски не нашлось открытого сектора ≥8°, это дефект подбора сцены, не продукта) | 130° | да | да | 7 / 0 |
| r3 | 130° | да | да | 7 / 0 |
| f92 | 92° (как реальный FOV) | да | да (фаза D неприменима: сектор датчика кончается на краю маски) | 7 / 0 |
Стабильно: A цель не исполняется; C отметка остаётся (нет сообщений, пустой скан и закрытый сектор читаются как неизвестное, не как свободное); B baseline 7 lethal остаются, кандидат 0; D отметка остаётся и скан читает NaN; E baseline цель отклонена без движения (7 строк «collision ahead»), кандидат идёт (0,9–2,1 м, итог ABORTED по прежним блокерам MC, не по collision).
**Абляции** (предыдущая редакция, до замены порога покрытием; выводы про два изменения остаются в силе): только `inf_is_valid` на старом скане — пустой скан СТИРАЕТ отметку настоящего препятствия и отметка вне FOV стирается (небезопасно); только новый формат скана без `inf_is_valid` — баг остаётся. Нужны оба изменения вместе.

## Вердикт: **GO для twin; кандидат готов к ревью.** На робот не применялось.
Ограничения:
- twin не запускает сам `level_bridge`: плант выдаёт скан в формате кандидата (функция идентична, parity-тест); сам bridge проверен юнитами и реальными облаками, не на живом FAST-LIO;
- сектор плант-скана 130° (или 92°) — модель, маска FOV из измерений;
- trial03 (отметка сразу за краем FOV после доворота корпуса) этим патчем не лечится по замыслу, остаётся открытым;
- слепая зона измерена стоя; препятствия ниже ~0,34 м скан не видит (существующий пробел);
- «покрытие» на реальном `/cloud_registered` не измерено (нет bag); безопасная сторона при ошибке — неизвестное.
